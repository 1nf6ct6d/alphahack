# Альфа Контекст

ML-библиотека и материалы команды для Alfa Hack 2026, трек новостной аналитики корпоративных клиентов. Цель системы — связывать внешние события с контекстом конкретной компании и объяснять возможный бизнес-механизм с сохранением источников, условий и неизвестных данных.

## Текущее состояние

**ML COMPLETE WITH EXTERNAL DEPENDENCIES** — реализованы локальные вычисления, детерминированное ранжирование и инфраструктура оценки. Это прототип библиотеки. Backend, сборщик полного бизнес-профиля, проекция MLView, сбор и нормализация реальных новостей, хранилище, публичный API и полное приложение в этом репозитории не реализованы.

Вычисления и демонстрации можно запускать без LLM API и платных запросов. Синтетические результаты не подтверждают качество на реальных новостях или готовность производственного сервиса.

## Структура

| Каталог | Назначение |
|---|---|
| ml_audit/ | Аудит CSV: структура, пропуски, дубликаты, конфликты и покрытие контрагентов |
| ml_features/ | Платёжные и групповые признаки, точные суммы, границы неопределённости и DerivedMetric |
| ml_ranking/ | Релевантность готовых нормализованных событий, доказательства, регуляторные проверки и ранжирование CFO/CEO |
| ml_evaluation/ | Precision/Recall/nDCG, отраслевой baseline, замороженные наборы и независимая разметка |
| examples/ | Автономный пример Python-библиотеки на синтетических данных |
| tests/ | Модульные и интеграционные тесты, синтетические фикстуры, проверка контрактов |
| bce_lab/ | Лаборатория Prompt Engineer для проверки промптов; не Backend и не рабочий BCE-конвейер |

Исходные банковские CSV, локальные окружения, приватные конфигурации, результаты LLM и сгенерированные отчёты не входят в Git.

## Окружение и установка

Проверенное окружение — Windows и Python 3.14.0. Исходники используют возможности Python 3.11+, но отдельная совместимость со всеми младшими версиями не подтверждена. Команды ниже рассчитаны на PowerShell и запуск из корня репозитория.

```powershell
py -3.14 -m venv .venv_win
.\.venv_win\Scripts\python.exe -m pip install -r requirements-ml.txt -r requirements-dev.txt
.\.venv_win\Scripts\python.exe -m pip check
```

requirements-ml.txt фиксирует runtime-зависимости jsonschema и referencing. requirements-dev.txt сохраняет зависимости существующего стенда. Алгоритмам не нужны тяжёлые ML-библиотеки, API-ключ или доступ к новостному сервису.

## Пример библиотеки

```powershell
.\.venv_win\Scripts\python.exe -B -X utf8 -m examples.ml_library_usage
```

Пример создаёт временные синтетические CSV, рассчитывает платежи и группы, сериализует DerivedMetric, отдельно загружает готовые синтетические MLView/CompanyBusinessProfile, ранжирует нормализованные события и выводит JSON. Он не вставляет признаки одной компании в профиль другой и не реализует сборщик Backend.

Основные импорты:

```python
from ml_features import (
    compute_payment_features, compute_group_features,
    serialize_derived_metrics, serialize_group_derived_metrics,
)
from ml_ranking import NewsEvent, rank_news, serialize_ranking
from ml_evaluation import evaluate_dataset
```

Полные сигнатуры, схемы входов, выходов и выполняемые примеры приведены в [финальной передаче Backend](docs/ML_BACKEND_HANDOFF_FINAL.md).

## Проверки

```powershell
.\.venv_win\Scripts\python.exe -B -X utf8 -m unittest discover -s tests -p "test_*.py"
.\.venv_win\Scripts\python.exe -B -X utf8 -m unittest discover -s tests -p "test_ml_integration_smoke.py" -v
```

Следующие команды проверки контрактов и лаборатории выполняйте **только в отдельной временной копии проекта**:

```powershell
.\.venv_win\Scripts\python.exe -B -X utf8 tests/validate_all.py
.\.venv_win\Scripts\python.exe -B -X utf8 -m bce_lab selftest
```

Последние две команды следует выполнять **в отдельной временной копии** проекта: validate_all пересоздаёт фикстуры, а selftest создаёт локальные результаты. Лабораторный selftest использует локальную имитацию на 127.0.0.1. Платный live-режим для обычной проверки не требуется. Описание стенда — в [bce_lab/README.md](bce_lab/README.md).

## Контракты и ответственность

Backend получает готовые ML-функции и отвечает за CompanyBusinessProfile assembly, MLView projection, сохранение версий и доказательств, API, доступ пользователей, сбор новостей и интеграцию с LLM-агентом. Ранжировщик потребляет существующие контракты и не создаёт профиль вместо Backend.

Business и Prompt Engineer должны согласовать таксономию факторов, классификатор ОКВЭД, нормализацию событий, пространство ID доказательств и независимую разметку. Утверждённого EventCandidate и реальной размеченной контрольной выборки в текущем workspace нет. Тестовые KB и каталог лаборатории не являются производственной экспертной базой.

## Данные и ограничения

Неизвестные значения остаются неизвестными. Дубликаты платежей не удаляются автоматически, конфликтующие профили не разрешаются произвольно, платёжные связи не доказывают поставку. Аддитивность строк — отдельное явное допущение. Регуляторные правила консервативны и не заменяют полноценную юридическую проверку. Метрики на искусственных сценариях проверяют инфраструктуру, а не реальную эффективность модели.

Данные для локального расчёта размещаются в data/raw/ или data/private/ и не публикуются. Не добавляйте банковские CSV, содержимое локальных отчётов или credentials в исходники и документацию. Для лаборатории ключ предусмотрен через переменную окружения BCE_LLM_API_KEY; создавать файл .env для запуска ML-библиотеки не требуется. Безопасные lab.config.example.json и tariffs.example.json являются шаблонами, приватные lab.config.json и tariffs.json исключены.

Перед каждым commit проверяйте git status и состав индексируемых файлов. Gitignore исключает пути, но не проверяет содержимое новых исходников и документов; исходные банковские данные в этот репозиторий не включаются.
