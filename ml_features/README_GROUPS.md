# ML-1B — группы компаний

Модуль расширяет ML-1A, не формируя полный CompanyBusinessProfile и не изменяя JSON Schema или MLView. Вычисления работают локально, без LLM и новых зависимостей.

## Что считается известным

Группа компании подтверждена в пределах выгрузки, если её ID есть в справочнике, профиль не конфликтует и GROUP_ID непустой. Используются те же `profile_status` и `confirmed_group`, что в ML-1A. Любой конфликт полей профиля исключает ID из подтверждённого состава, даже если GROUP_ID в спорных строках совпадает. U_428697 всегда неоднозначен. Пропуск GROUP_ID означает неизвестную принадлежность, а не независимость компании.

`group_size` — число уникальных однозначных ID с тем же подтверждённым GROUP_ID, включая целевую компанию. Совпадающие записи одного ID считаются одним юрлицом. Показатель описывает наблюдаемый надёжный состав в данном CSV, а не гарантированно полный состав реальной группы. Для неизвестной группы `group_size = null`, список подтверждённых участников неизвестен, DerivedMetric не публикуется.

Счётчики неопределённой принадлежности разделены:

- `directory_unassigned_company_count` — уникальные наблюдаемые ID всего справочника, для которых группа не подтверждена.
- `unresolved_candidate_member_count` — такие ID, у которых хотя бы одна исходная запись содержит GROUP_ID целевой группы. Они показаны как спорные кандидаты и не входят в group_size или сумму выручки.
- Строки без ID компании учитываются отдельно: число юрлиц за ними установить нельзя.

Неизвестные GROUP_ID без связи с конкретной группой не объявляются её участниками или подтверждёнными неучастниками. Даже при отсутствии спорных кандидатов полнота реального состава неизвестна, поэтому `coverage` у DerivedMetric group_size остаётся `null`.

## Выручка

REVENUE_COMPANY — выручка юрлица за 2025 год в RUB. По каждому подтверждённому участнику сохраняются наблюдаемая строка выручки, её статус и число записей источника. Конечные неотрицательные числа пригодны; ноль допустим. Значение 1000 в любой числовой записи — техническая заглушка. Пропуски, заглушки, отрицательные, нечисловые и бесконечные значения не включаются в сумму; причины и счётчики остаются в отчёте.

`reported_member_revenue_sum` — точная сумма пригодной выручки по уникальным подтверждённым участникам. Если пригодных наблюдений нет, сумма неизвестна, а не равна нулю. `valid_revenue_coverage` — число участников с пригодной выручкой / число подтверждённых участников. Пропуски, заглушки и другие ошибки считаются по юрлицам, не по дублирующим строкам. При неизвестном составе группы эти счётчики и покрытие тоже неизвестны.

Сумма может быть частичной даже в пределах выгрузки. Она **не является подтверждённой консолидированной выручкой**: внутригрупповые обороты не исключены. `confirmed_consolidated_group_revenue` всегда `null`. Если столбца выручки нет, состав группы всё равно рассчитывается, а выручка отмечается отсутствующей. Рыночная доля по CSV не выводится.

## Платёжные связи

Используются агрегаты ML-1A. Каждый пригодный внешний получатель относится к подтверждённой той же группе, подтверждённой другой группе либо неизвестной группе. Последняя категория включает отсутствующие профили, технические ID, конфликтующие профили, однозначные профили без GROUP_ID, а также случай неизвестной группы целевого плательщика.

Для внешней пригодной суммы E, подтверждённой суммы той же группе S и неразрешённой суммы U границы равны S / E и (S + U) / E. Точная доля известна только при E > 0 и U = 0. Неизвестная принадлежность получателя нулевой суммы остаётся неизвестной, но не расширяет денежную границу. При E = 0 доли `null`. Правила обработки непригодных сумм, самоплатежей и аддитивности сохраняются из ML-1A.

Дополнительно проверяются классификация каждого получателя и равенство E = S + D + U. Отдельные счётчики показывают неразрешённых получателей, которые всё же есть в справочнике, включая однозначные профили с отсутствующим GROUP_ID. Условие аддитивности не превращается в подтверждённый факт. Год и конец платёжного периода неизвестны.

## Публичная функция и запуск

YOUR_COMPANY_ID и OTHER_COMPANY_ID — заполнители для строковых ID из локальной выгрузки; замените их перед запуском.

```python
from ml_features import compute_group_features, compute_payment_features

payments = compute_payment_features(
    "YOUR_COMPANY_ID",
    "data/raw/df_Uid_data_hack.csv",
    "data/raw/df_Uid_payment_hack.csv",
    assume_additive_rows=True,
)
groups = compute_group_features(
    "YOUR_COMPANY_ID",
    "data/raw/df_Uid_data_hack.csv",
    payment_features=payments,
)
```

Вместо `payment_features` можно передать третий аргумент `payment_csv` и `assume_additive_rows=True`: ML-1A будет вызван один раз. Платёжный CSV повторно не сканируется ради группового анализа. Без обоих платёжных аргументов вычисляются только состав и выручка группы; платежи остаются неизвестными. Эти два способа передачи платежей взаимоисключающие.

При повторном использовании объекта проверяются ID компании, SHA-256 версии справочника, классификация получателей и согласованность агрегатов. Повторного чтения платёжного CSV нет: объект относится к версии файла, указанной в его исходном манифесте, а не к гарантированно текущим байтам по тому же пути. Режим аддитивности берётся из переданного объекта; включить суммирование поверх объекта без агрегатов нельзя.

```powershell
.\.venv_win\Scripts\python.exe -B -X utf8 -m ml_features.group_cli --company-id YOUR_COMPANY_ID --assume-additive-rows
.\.venv_win\Scripts\python.exe -B -X utf8 -m ml_features.group_cli --company-id OTHER_COMPANY_ID --assume-additive-rows
.\.venv_win\Scripts\python.exe -B -X utf8 -m unittest discover -s tests -p "test_*.py" -v
```

CLI поддерживает `--data-dir`, `--output-dir`, `--encoding` и `--without-payments`. Результаты: `reports/ml1b_group_features_<ID>.json` и `.md`; они исключены через `.gitignore`. Временных меток нет, деньги и доли считаются точно через Fraction, форматирование переиспользуется из ML-1A. Источники сохраняются с SHA-256, CSV не изменяются. Платёжный файл не загружается в объединённую таблицу; справочник читается отдельно для группового анализа.

## Контракт и ограничения

Сериализатор ML-1B добавляет только существующий DerivedMetric `group_size`. Его evidence — реально наблюдаемые SYNTHETIC_U и GROUP_ID целевой компании. Полный источник подсчёта — манифест CSV и перечень подтверждённых участников. Суммы выручки, её покрытие и диагностика остаются вне DerivedMetric. Шесть платёжных метрик доступны через неизменённый сериализатор ML-1A.

Надёжность group_size маркируется не выше medium из-за неизвестной полноты реального состава; при спорных кандидатах — low. Это консервативная маркировка данных, не вероятность и не калибровка модели. Наличие общего GROUP_ID не доказывает контроль, зависимость или единую цепочку поставок.
