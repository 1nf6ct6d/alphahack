# Исправления v0.1 → v0.2

Исходная `business_context_engine_spec.md` (v0.1) не изменена. Новая версия: `business_context_engine_spec_v0.2.md`.

## Схемы
| № | Ошибка в v0.1 | Исправление |
|---|---|---|
| S-1 | `allOf` с общей схемой `Statement` (`additionalProperties:false`) и дополнительными полями (`category`, `topic`…) отклонял любой корректный факт/гипотезу (воспроизведено тестом A5) | каждый объект определён самостоятельно; `allOf` остался только для `if/then`-ограничений без `properties` рядом с `additionalProperties:false` |
| S-2 | JSON-схема содержала `/* … */`-комментарии | комментарии удалены; пояснения — в `description` и спецификации |
| S-3 | Схема была не отдельным файлом, а фрагментом Markdown; схема LLM (В.3) — прозой | созданы 4 файла схем + проверка в коде |
| S-4 | `EvidenceRef.value` — скаляр, а `derived.value` — объект/массив: ссылка на метрику невозможна | значения метрик скалярны; структура в `breakdown` |
| S-5 | Паттерн id `(F\|D\|H\|S)` не покрывал конфликты и пропуски; id LLM и итоговые id не различались | `C-`, `M-`; локальные id LLM (`h1`, `s1`) и стабильные id профиля + `local_id_map` |
| S-6 | LLM обязывали ставить `epistemic_status`, но в схеме ответа его не было; лимиты 8/10 в промпте и 12/15 в схеме без объяснения | LLM не формирует статус и кодовые поля; лимиты разведены: 8/10 для LLM, 12/15 для профиля (с KB) |
| S-7 | Ограничения состояний не выражены в схеме | `if/then`: `unusable`, `no_inference`, `sector_only`, режимы с LLM, `kb_fallback`, `llm_partially_validated` |
| S-8 | Не было схем для получателей | `MLView`, `InterpreterView`, `UIView` |

## Логика
| № | Противоречие | Исправление |
|---|---|---|
| L-1 | `usability` не определён; S3 ожидал `limited`, а правило промпта №12 — `sector_only` | четыре значения с явными условиями; S3 → `sector_only` |
| L-2 | Отсутствие ОКВЭД: в одном месте «blocking → unusable», в другом `sector_only` невозможен | таблица `industry_identification`; только название без сопоставления → `unusable`, код не подбирается моделью |
| L-3 | `pipeline_mode=degraded_no_llm` смешивал непригодные данные и сбой LLM (S5) | `llm_validated`, `llm_partially_validated`, `kb_fallback`, `no_inference`; матрица допустимых сочетаний |
| L-4 | Единицы выручки и платежей не заданы в ТЗ, но использовались (`size_class`, суммы, порог) | статусы `…_semantics_status`; метрики `unit_free` / `requires_confirmed_unit`; запрет сумм и порогов при `unknown` |
| L-5 | Нет различия «нет данных» и «подтверждённо нет» | `field_states`: `missing` ≠ `confirmed_absent_in_scope` (с областью: банк, база ФТС) |
| L-6 | Отсутствие РКО при других продуктах считалось ошибкой (CONF-PROD-TYPE) | правило удалено |
| L-7 | Выручка < 15 млрд считалась конфликтом (CONF-REV-THRESHOLD) | удалено; `target_segment_applicability`, `usability` не снижается |
| L-8 | `FTS_FLAG=1` при пустой стране называлось противоречием | это пропуск; противоречие только `FTS_FLAG=0` при заполненной стране |
| L-9 | Внутригрупповые платежи, покрытие контрагентов, `NEGATIVEMARK` числились «конфликтами» | ограничение интерпретации / метрика покрытия / `semantics_unknown` |
| L-10 | Правила возраст-стадия, регион-город, выручка-штат требовали неизвестных словарей и порогов | перенесены в `requires_dictionary`/не MVP и не считаются выполненными без справочника |
| L-11 | Тесты использовали «реалистичные» значения (города, страны, градации), то есть выдумывали свойства датасета | условные токены, оговорка в фикстурах и спецификации |
| L-12 | Нулевые флаги продуктов неоднозначны (0 = нет в этом банке) | область `scope=bank`, запрет как основания вывода; для потенциальных клиентов `uninformative` |

## System Prompt
| № | Проблема | Исправление |
|---|---|---|
| P-1 | Уверенность зависела от числа признаков («high — ≥2 независимых») | три аспекта: `data_reliability` (код), `inference_support` (LLM по смыслу), `uncertainty_sources`; итог считает код |
| P-2 | Модель не получала список допустимых ссылок, проверить evidence было нечем | `evidence_index` + проверка кодом |
| P-3 | Не было каталога факторов | закрытый `factor_catalog` |
| P-4 | Не было правил для единиц, группы, потенциального клиента, области «нуля» | добавлены |
| P-5 | Запреты на выдумывание | сохранены полностью |

## Тестовые сценарии
S3: `limited` → `sector_only`. S5: `degraded_no_llm` → `no_inference`. S2: удалены невыполнимые без словарей проверки и конфликт по выручке, добавлены `FTS`-противоречие, `CL_TYPE`, платежи себе и неизвестные единицы. S1/S4 уточнены (единицы, uncertainty).
