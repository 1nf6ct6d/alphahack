# ML-0 — обследование данных

Автономный инструмент аудита, не реализация BCE или расчёта признаков ML-1. Использует только стандартную библиотеку Python 3.11+. Установка дополнительных зависимостей и ключ LLM не нужны.

Из корня проекта в PowerShell:

```powershell
.\.venv_win\Scripts\python.exe -B -X utf8 -m ml_audit
.\.venv_win\Scripts\python.exe -B -X utf8 -m unittest discover -s tests -p "test_ml_audit.py" -v
```

Параметры:

```powershell
.\.venv_win\Scripts\python.exe -B -X utf8 -m ml_audit --data-dir data/raw --output-dir reports --encoding auto
```

В Linux/macOS используется соответствующий Python из окружения. В указанной входной папке и её подпапках ищутся точные имена `df_Uid_data_hack.csv`, `df_Uid_payment_hack.csv`, `df_Fid_Uid_link_hack.csv` без учёта регистра. При нескольких одноимённых файлах инструмент останавливается, не выбирая один произвольно. При отсутствии файлов создаётся неполный отчёт с `null` для неизвестных размеров.

Результаты:

- `reports/ml0_data_audit.json` — структурированные данные, источники и SHA-256, методика, ограничения, счётчики и ограниченные примеры конфликтов.
- `reports/ml0_data_audit.md` — описание результатов и определений на русском.

Отчёты не содержат временных меток: повторный запуск на тех же путях, байтах файлов и настройках даёт тот же результат. Код возврата `0` означает, что все файлы прочитаны, а не отсутствие проблем качества; `1` — неполный аудит; `2` — ошибка запуска или неоднозначное расположение входных файлов.

## Чтение и числовые поля

Разделитель — `;`, кавычки и многострочные поля обрабатывает `csv.reader`. Все поля исходно остаются строками. ID и коды с ведущими нулями не преобразуются в числа; внешние пробелы сохраняются и считаются отдельно. Тип содержимого выводится по всем прочитанным значениям, не по выборке.

Автоматическая кодировка: UTF-32/UTF-16 по BOM; иначе полная строгая проверка UTF-8, затем CP1251. Повреждённый текст не заменяется символом `�`. Автоопределение CP1251 не может доказать правильность кодировки; это отмечается в ограничениях, при необходимости задайте `--encoding` явно.

Пропуски: пустота, пробельная строка, `null`, `none`, `nan`, `n/a`, `<na>` без учёта регистра. `NA`, `0`, `-1` не считаются пропусками автоматически. У неизвестных категорий не выдумываются словари. Проверяются денежные поля, PAY_CNT и известные продуктовые/ФТС-флаги; смысл NEGATIVEMARK остаётся неизвестным.

Числа проверяются через Decimal без двоичного float. Допускаются десятичная точка/запятая и экспоненциальная запись; разделители тысяч не угадываются. Суммы и счётчики должны быть неотрицательными, PAY_CNT — целым, флаги — 0 или 1. Выручка `1000` в любой числовой записи — заглушка. Выручка относится к 2025 году, денежные поля — RUB; для платежей известен только день начала 1 января, год и конец периода остаются `null`.

## Дубликаты, конфликты и знаменатели

Точный дубликат — одинаковые разобранные поля CSV до нормализации. JSON содержит число разных записей, повторяющихся групп, всех строк в них и повторов сверх первого. Разное оформление кавычек одного и того же значения не создаёт разные записи. Ничего не удаляется.

Конфликт компании — один SYNTHETIC_U с различающимися полями после нормализации только маркеров пропуска. Разные текстовые записи числа также считаются различием. Первая запись хранится лишь для сравнения, не выбирается как достоверная. Примеры ограничены 20 ID и 5 значениями поля, полные счётчики не ограничены. Строки без ID учитываются отдельно.

Размеры групп считаются по уникальным ID компаний с единственным наблюдаемым GROUP_ID, включая проверку противоречия «пропуск против значения». Неоднозначные принадлежности исключаются только из распределения размеров, а не из исходных данных. Наблюдаемые группы без однозначных участников получают размер 0. Полнота пригодной выручки считается по всем строкам, без удаления повторов; пропуски, заглушки, отрицательные и нечисловые значения непригодны.

Покрытие справочником приводится отдельно для всех уникальных участников, уникальных внешних получателей платежей компаний из справочника и строк этих внешних платежей. Самоплатежи исключаются из двух последних показателей, неизвестные получатели остаются в знаменателе. Строки без полного набора ID не входят в покрытие внешних связей; неправильные суммы не скрывают существование связей. Денежное покрытие и финансовые агрегаты не рассчитываются на этапе ML-0.

Повторы направленной пары PAYER → BENEFICIARY считаются отдельно от точных дубликатов. Период и детализация строки платежей не подтверждены; повтор пары не доказывает ошибку или необходимость суммирования. Связи не объявляются отношениями поставки, GROUP_ID не доказывает контроль или зависимость, выручка отдельного юрлица не определяет принадлежность всей группы к корпоративному сегменту.

Пустой знаменатель даёт `null`, а не 0%. Строки неправильной длины остаются в общем числе строк и учёте дубликатов, но не в анализе связей. Отсутствие обязательных столбцов отключает анализ связей соответствующего файла. Ошибка чтения оставляет явно неполный результат по прочитанному префиксу. При недоступном справочнике покрытие и число неизвестных контрагентов равны `null`.

## Ресурсы и границы изменений

CSV читаются потоково. Платёжные строки и пары не загружаются в большую таблицу и не объединяются с каталогом через join. Точные повторы хранятся во временной SQLite-базе на диске с кэшем 8 МБ. В памяти остаются справочник компаний, наблюдаемые конфликты и счётчики уникальных ID. Для временной базы нужно свободное место, сопоставимое с размером CSV и их индексов. Временная база удаляется после аудита, включая обработанные ошибки.

`data/raw/` и два локальных отчёта исключены через `.gitignore`. Входные CSV, схемы, фикстуры и LLM-стенд не изменяются. Обычный запуск `tests/validate_all.py` перезаписывает фикстуры, а `bce_lab selftest` создаёт результаты: существующие проверки следует запускать в отдельной временной копии проекта. Новые unit-тесты используют собственные временные синтетические CSV.
