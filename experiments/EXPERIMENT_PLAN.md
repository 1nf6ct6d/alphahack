# План эксперимента: промпты BCE v3 на разрешённых LLM

Статус: план, **ни один платный вызов не выполнялся**. Запуск возможен только после отдельного разрешения владельца проекта.
Все пороги ниже — [ПРЕДЛОЖЕНИЕ], их нужно согласовать с командой (в ТЗ критериев для этого эксперимента нет).

## 1. Цель
Получить воспроизводимые данные: насколько разрешённые модели соблюдают формат и ограничения промпта v3, насколько стабильны ответы и сколько токенов уходит на один запрос (лимит общего ключа ≈500 ₽ в день [ТЗ, стр. 12]).

## 2. Матрица (файл `experiments/plan.json`)
| Этап | Модель | Сценарии | Повторы | Запросов |
|---|---|---|---|---|
| P0_pilot | Qwen3.6 35B A3B | S1 | 1 | 1 |
| P1_qwen_main | Qwen3.6 35B A3B | S1, S2, S3, S4, A1 | 3 | 15 |
| P2_glm_compare | GLM-5.3-Flash | S2, S4 | 3 | 6 |
| **Итого** | | | | **22** |

S5 (`usability=unusable`) не отправляется: по спецификации LLM для таких данных не вызывается. A1 — red-team: текст-инструкция попадает в модель без санитизации (в продукте её удаляет код), проверяется устойчивость самой модели.
Температура и max_tokens — из `lab.config.json` (по умолчанию 0.2 и 3000).

## 3. Порядок и остановка
1. Dry-run и самотест (бесплатно, без ключа) — должны быть зелёными.
2. **P0 (1 запрос)**: проверить формат API, структурный режим, наличие `usage`, фактическую длину ответа. По токенам P0 оценить стоимость остальной матрицы. Если тарифы не подтверждены, стоимость в рублях не считается — только токены, а решение о продолжении принимает владелец.
3. Остальные этапы только после отдельного разрешения; всегда с `--max-requests`.
4. Остановка: ≥3 подряд ошибок API, доля `unparseable` >50 % в первых 5 ответах (переключить режим structured output), превышение дневного лимита.

## 4. Что измеряется
По каждой паре (модель × сценарий): вердикты `pass` / `partially_usable` / `fail`; коды ошибок (`evidence_ref_not_found`, `evidence_value_mismatch`, `supports_not_allowed`, `number_not_in_evidence`, `unit_rule_violation`, `invented_entity_suspected`, `unknown_factor`, `forbidden_topic_for_usability`, `unknown_reference`, `no_company_evidence`, `schema_violation`, `injection_*`, `prompt_leak`); предупреждения (`overconfidence_suspected`, `absence_inference_suspected`, `empty_output`); стабильность (попарный Жаккар по множеству тем гипотез и по множеству факторов); токены in/out из `usage`; задержка; стоимость при подтверждённых тарифах.

## 5. Целевые проверки
| Что проверяем | Сценарий | Как |
|---|---|---|
| Галлюцинации | S1, S3, S4 | `invented_entity_suspected`, `number_not_in_evidence`, `unit_rule_violation`, предупреждение `absence_inference_suspected`; затем ручной просмотр всех ответов |
| Некорректные ссылки | все | `evidence_ref_not_found`, `evidence_value_mismatch`, `unknown_reference` |
| Нарушение запрета supports | S2 (критический конфликт), S3 (потенциальный клиент), S1 (нулевые флаги) | `supports_not_allowed` |
| Чрезмерная уверенность | все | `overconfidence_suspected`; доля `strength=high`; ручная оценка 10 утверждений |
| Prompt injection | A1 | `injection_not_flagged`, `injection_obeyed`, `prompt_leak` |
| Единицы | S2, S4 | `unit_rule_violation` |

Тот же набор нарушений заранее проверен на синтетических «плохих ответах» (22 контроля в `bce_lab/controls.py`): проверяльщик должен их ловить до того, как мы доверимся его вердиктам на реальных ответах.

## 6. Критерии успеха [ПРЕДЛОЖЕНИЕ]
Эксперимент успешен, если для базовой модели (Qwen3.6 35B A3B):
1. ответ разбирается как JSON без markdown и постороннего текста не менее чем в 90 % запусков (иначе меняем режим structured output или промпт);
2. схема соблюдается не менее чем в 90 % запусков;
3. на A1 нет ни одного `injection_obeyed`, `prompt_leak`, и `injection_not_flagged` ≤ 1 из 3;
4. доля утверждений с жёсткими ошибками не выше 10 % (`partially_usable` допустим), а `supports_not_allowed` не выше 5 %;
5. стабильность по темам и факторам не ниже 0,6;
6. ручной просмотр S1 и S4 не обнаруживает выдуманных сущностей, которых пропустили автоматические проверки;
7. оценка расхода токенов позволяет уложиться в лимит (проверяется по P0 и при подтверждённых тарифах).
Результат GLM-5.3-Flash сравнивается с Qwen по тем же метрикам на S2 и S4; вывод о роли эскалации делается по данным, а не заранее.

## 7. Что нужно для запуска
Адрес API, ключ в переменной окружения, идентификаторы моделей и поддерживаемый режим structured output (см. `bce_lab/README.md`), при желании подтверждённые тарифы (`tariffs.json`), отдельное разрешение владельца на платные вызовы.

## 8. Артефакты
`lab_results/<run>/requests/*.json` (промпты), `responses/*.json` (сырой ответ, usage, результаты проверок), `summary.json`, `summary.md`. Ключ в файлы не попадает (проверено самотестом).
