## Расхождения со спецификацией v0.2, которые нужно внести в неё (сама спецификация не менялась)
1. **Раздел 4.1, 7, 8, 12.1 (S2).** По новому правилу поля критического конфликта не могут быть `supports`. Для `industry_identification=ambiguous` это означает: гипотез по ОКВЭД нет, остаются только основанные на других признаках. Прежнее «код приоритетнее, `data_reliability=low`» перестаёт быть путём к отраслевым гипотезам. Для согласованности изменён сценарий S2 (`tests/scenarios.py`): отраслевая гипотеза и чувствительность убраны, остался вывод о группе; ожидаемый результат консервативный.
2. **Раздел 10.2/8.** В контракт `evidence_index` добавляется вычисляемое поле `supports_allowed` (правила в `bce_lab/render.py`: `blocked_refs`, `build_evidence_index`).
3. **Раздел 8.** Причины отбраковки в `provenance.validation.dropped_statements[].reason` дополнены: `supports_not_allowed`, `unknown_reference`, `invented_entity_suspected`, `injection_not_flagged`, `injection_obeyed`, `prompt_leak` (изменена схема профиля).
4. **Раздел 9.** Таблица переменных шаблона: убраны `*_enum`, добавлен `allowed_topics`.
5. **Раздел 4.5.** До ответа организаторов (D1) нулевые флаги банка и `FTS_FLAG=0` не используются как `supports` (в v0.2 было сказано в тексте, теперь это механизм).

## Ограничения
Формат API организаторов, тарифы и возможности structured output неизвестны; KB и каталог факторов — тестовые заглушки; оценка токенов в dry-run — грубая (символы/3), не биллинг; проверки живого пути выполнены только на локальном mock-сервере.
